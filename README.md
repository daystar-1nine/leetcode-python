## 📖 Problem Documentation Standard (16 Sections)

Each problem directory includes a complete `README.md` following this structure:
1. **Problem Information** - Title, difficulty, tags, LeetCode link
2. **Problem Overview** - Detailed description, inputs/outputs, and official examples
3. **Intuition** - Core insight and mental model
4. **Thought Process** - Step-by-step logic accompanied by a Mermaid flowchart
5. **Concepts Used** - Key DSA concepts explained and contextualized
6. **Algorithm Used** - Formal categorization, design pattern, and justification
7. **Code Walkthrough** - Line-by-line explanation of the Python solution
8. **Dry Run** - Comprehensive state tracking table through representative test cases
9. **Complexity Analysis** - Formal time and space complexity with Big-O notation
10. **Edge Cases** - Boundary conditions, corner cases, and handling mechanisms
11. **Alternative Approaches** - Brute force vs optimized comparison
12. **Common Mistakes** - Pitfalls, traps, and anti-patterns to avoid
13. **Interview Questions** - Real-world interview follow-ups and discussion points
14. **Similar Problems** - Related LeetCode problems for spaced repetition
15. **Learning Summary** - Key takeaways and pattern recognition notes
16. **Optimization Notes** - Profiling and memory/runtime optimizations

---

## 🌿 Git Commit Conventions

Commit messages in this repository strictly adhere to conventional commits:
- `feat(topic): add <number>-<Problem-Name> solution with explanation`
- `docs: update repository progress and README`
- `refactor(problem): optimize documentation or code formatting`
